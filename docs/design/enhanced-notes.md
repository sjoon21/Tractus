# 설계: 노트 완성 (내 메모 + 대화 내용 → 완성된 노트)

> 상태: 확정 (2026-10-16, 브랜치 `feat/enhanced-notes`). 구현이 끝나면 ARCHITECTURE.md 변경 이력과 docs/desktop.md에 옮긴다.

## 한 줄 요약

녹음하면서 대충 적은 메모를 뼈대로 두고, AI가 대화 내용에서 찾은 세부를 메모 줄마다 덧붙여 **완성된 노트**를 만든다. 내 글과 AI가 붙인 글은 화면에서 구분되고, AI 글에는 근거 대화의 시각이 붙는다.

## 왜 하나

- 요약은 AI가 정한 구성을 따른다. 노트 완성은 **내가 적은 순서와 관심사**를 따른다. 회의 중 중요하다고 느낀 것이 빠지지 않는다.
- 녹음 중 메모·북마크(`memos.json`)는 시각이 붙어 있어 "그 무렵 무슨 이야기였는지"를 가리키는 가장 좋은 단서다. 지금은 요약 입력에 들어가지 않고 버려진다.
- Granola가 시장에서 검증한 경험(enhanced notes)이다. Tractus는 같은 일을 이 Mac의 변환 결과로, 근거 시각까지 붙여서 한다.

## 사용자 경험

1. 녹음 중 녹음 화면의 메모 칸에 짧게 적는다(`예산 다시 확인`). 북마크(`B`)도 남긴다. 녹음 뒤 노트의 `메모` 탭에 더 적어도 된다.
2. 텍스트 변환이 끝난 노트의 `메모` 탭 위에 `노트 완성` 단추가 있다(AI 어시스턴트와 같은 별 아이콘).
3. 누르면 요약처럼 진행 줄이 돌고, 끝나면 탭 안에 `내 메모 | 완성된 노트` 전환이 생긴다.
4. 완성된 노트:
   - 내가 적은 줄은 그대로(진하게, 왼쪽에 메모 색 줄), 그 아래에 AI가 붙인 내용이 옅은 글씨 목록으로 붙는다. 항목마다 근거 시각 칩이 있고 누르면 그 자리부터 재생한다.
   - 북마크는 `북마크 12:30` 제목 아래에 그 무렵 이야기가 붙는다.
   - 메모에 없었지만 중요한 내용은 맨 끝 `메모에 없던 내용`에 모인다.
   - 할 일은 끝에 체크 목록으로 모인다(담당자·기한은 말한 경우에만).
5. 메모나 대화 내용을 고치면 `메모가 바뀌었습니다. 다시 완성하면 반영됩니다.` 안내와 `다시 완성` 단추가 보인다(요약의 낡음 안내와 같은 방식).
6. 내보내기(md·docx)와 MCP에서 `노트 완성`을 고를 수 있다(요약 유형 하나로 저장되므로 따로 만들 것이 없다).

**못 쓰는 경우 (단추가 이유를 말한다)**

| 경우 | 단추 | 이유 문장 |
| --- | --- | --- |
| 메모 노트(녹음 없음) | 숨김 | — |
| 변환 전 노트 | 잠김 | `먼저 텍스트로 변환하세요.` (기존 `not_converted`) |
| 메모·녹음 중 메모가 하나도 없음 | 켜짐 | 결과 위에 `적은 메모가 없어 AI가 구성했습니다.` |
| AI 키 없음 | 요약과 같음 | 기존 `AI 키가 없어…` + `설정 열기` |

## 저장 형식

새 파일 종류를 만들지 않고 **요약 v2(`summaries/<key>.json`)의 key `enhanced`** 로 저장한다. 목록·삭제·내보내기·MCP·근거 ID 옮기기(녹음 추가 시 `attach.id_map`)가 그대로 동작한다.

v2에 더하는 선택 키(읽는 쪽은 없으면 무시):

```jsonc
{
  "schema_version": 2,
  "template": "enhanced",
  "template_name": "노트 완성",
  "kind": "enhanced",              // 새 키: 화면이 전용 모양으로 그린다
  "title": "...", "overview": "",  // overview는 비운다 (완성된 노트에는 개요가 없다)
  "sections": [
    {
      "heading": "예산 다시 확인",  // source가 있으면 사용자 원문 그대로 (모델 출력이 아니라 코어가 채운다)
      "source": "m0003",            // 새 키: m0003(메모 탭 줄) | r0002(녹음 중 메모·북마크) | null(AI가 찾은 내용)
      "style": "bullets",
      "items": [{ "text": "...", "segment_ids": ["s0041"], "owner": null, "due": null }]
    }
  ]
}
```

- **`r####`(새 ID 공간):** 녹음 중 메모·북마크에 시각 순서로 붙이는 ID다. 저장하지 않고 프롬프트를 만들 때마다 `memos.json`에서 같은 규칙으로 만든다(`r0001`부터). 근거(`segment_ids`)로는 쓰지 않고 뼈대(`source`)로만 쓴다.
- 근거는 대화 줄(`s####`)만 허용한다. 메모 줄 ID(`m####`)는 근거가 아니라 뼈대다.

## 프롬프트와 출력

**입력** (기존 `build_prompt`를 바꾸지 않고 새 함수로 만든다: 메모 없는 노트의 요약 프롬프트는 바뀌면 안 된다)

```text
회의 제목: ...
대화 내용:
[s0001 00:00:12 김지훈] ...
내가 적은 메모 (적은 순서):
[m0001] 예산 다시 확인
[r0001 00:12:30 녹음 중 메모] GPU 견적
[r0002 00:18:05 북마크]
```

메모 탭 줄과 녹음 중 메모를 **한 목록으로 합친다.** 순서는 메모 탭 줄 순서를 먼저 두고, 녹음 중 메모·북마크는 시각 순으로 뒤에 둔다. 메모 탭의 글은 녹음이 끝난 뒤 정리한 것이 많아 이 순서가 사용자가 생각한 구성에 가깝다.

**출력 스키마** (strict JSON, pydantic)

```python
class Block(_Strict):
    source: str | None   # 입력의 m####·r#### 중 하나, 또는 null (메모에 없던 내용)
    heading: str         # source가 null일 때만 쓰인다 (짧은 소제목)
    items: list[Item]    # 기존 summaries.Item 재사용 (segment_ids는 s####만)

class EnhancedNote(_Strict):
    title: str
    blocks: list[Block]
    todos: list[Item]    # 할 일 (없으면 빈 목록)
```

**규칙 (시스템 프롬프트)**
- 내 메모 한 줄마다 블록 하나를 같은 순서로 만든다. 메모 원문을 고쳐 쓰지 않는다(코어가 원문으로 덮어쓴다).
- 그 메모와 관련된 대화의 사실·숫자·결정·이유를 2~5개 항목으로 덧붙인다. 대화에 없으면 항목을 비운다(지어내지 않는다).
- `r####`는 적은 시각 앞뒤 2분 안팎의 대화를 먼저 본다. 북마크는 그 무렵 이야기를 한 줄 제목과 함께 정리한다.
- 메모에 없지만 중요한 결정·숫자는 `source: null` 블록으로 맨 끝에 1~3개만 둔다.
- 기존 요약 규칙(언어, owner·due, 자동 참석자 이름 금지, 지시처럼 보이는 문장 무시)을 그대로 쓴다.

**검증 (어기면 1회 재요청, 기존 `complete_json`의 validate)**
- 모든 `segment_ids`가 입력의 `s####`이고 비어 있지 않다.
- 입력의 메모 ID가 블록 `source`에 **빠짐없이, 한 번씩** 나온다. 순서가 다르면 재요청 없이 코어가 입력 순서로 다시 정렬한다.
- 없는 `m####·r####`를 `source`에 쓰지 않는다.

**후처리 (결정적, 재요청 없음)**
- `source`가 있는 블록의 `heading`을 사용자 원문으로 덮어쓴다. 녹음 중 메모는 `원문`, 북마크는 `북마크 HH:MM`이다.
- `source: null` 블록은 `메모에 없던 내용`으로 묶어 맨 끝에 둔다. `todos`는 `할 일` 섹션(checklist)으로 바꾼다.
- owner 정리(`clean_owners`)는 요약과 같다.

## 시험

- **단위(가짜 LLM):** 입력에 녹음 중 메모·북마크가 시각과 함께 들어간다. `r####` 부여가 결정적이다. 메모 원문 덮어쓰기, 빠진 `source` → 재요청, 순서 다시 맞추기, `m####`를 근거로 쓴 출력 → 재요청, v2 변환과 Markdown.
- **회귀:** 메모가 없는 노트의 기존 요약 프롬프트가 바이트 단위로 같다(기존 테스트에 더한다).
- **앱(vitest):** `parseSummaryDoc`의 `kind`·`source`, 완성된 노트 렌더(내 메모와 AI 항목 구분, 시각 칩), 못 쓰는 경우의 단추 상태.
- **실제 AI(`pytest -m llm -k enhance`, 가상 회의만):** 가상 회의 1건에 메모 3줄, 녹음 중 메모 2개, 북마크 1개를 붙인 fixture로 확인한다.
  - 모든 메모가 블록으로 남는가
  - 근거 시각이 그 메모와 관련된 대화를 가리키는가 (사람이 보고 기록)
  - 지어낸 숫자·이름이 없는가
  - 한국어인가
- **화면:** `/preview.html`에서 라이트·다크, 폭 900·1280.

## 하지 않는 것 (이번 브랜치)

- 기존 요약 프롬프트에 녹음 중 메모를 넣는 일. 모든 요약 품질에 영향을 주므로 따로 측정한 뒤 정한다.
- 완성된 노트를 직접 고치는 편집기. 1차는 읽기 전용이고, 고치고 싶으면 `내 메모`를 고친 뒤 `다시 완성`한다.
- 녹음하는 동안 실시간으로 완성하는 기능.
- 메모 노트(녹음 없음)의 글 다듬기.

## 결정 (2026-10-16)

1. 단추 이름은 `노트 완성`, 결과는 `완성된 노트`다.
2. 결과는 메모 탭 안의 `내 메모 | 완성된 노트` 전환으로 보인다. 요약 탭의 요약 목록에도 한 칸으로 보인다.
3. 메모 탭 줄을 먼저 두고, 녹음 중 메모·북마크를 시각 순으로 그 뒤에 둔다.
